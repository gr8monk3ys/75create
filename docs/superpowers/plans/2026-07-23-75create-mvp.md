# 75 Create MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the full MVP (F1–F10) of the 75 Create challenge tracker as a local-first Next.js web app that runs with `npm run dev`, backed by a repository interface swappable for Supabase later.

**Architecture:** Next.js App Router. Pure `challengeEngine` computes day states, streaks, and miss-policy outcomes deterministically (time injected, no I/O). A `Repository` interface abstracts persistence; `LocalRepository` uses localStorage + IndexedDB. React context (`AppProvider`) wires repo → engine → screens.

**Tech Stack:** Next.js, TypeScript, Tailwind CSS, Vitest, JSZip, browser Canvas/Notifications/IndexedDB APIs.

## Global Constraints

- All persistence goes through the `Repository` interface — feature code never touches `localStorage`/`IndexedDB` directly.
- `challengeEngine` is pure: current time is a parameter, never `Date.now()` inside.
- Rules number 3–7 and lock once a challenge starts (`status !== 'setup'`).
- Daily log ≤ 500 chars. Artifact image ≤ 5 MB, compressed client-side before store.
- Late-night buffer default 3 a.m., configurable; day boundaries use the user's stored timezone.
- Private by default — nothing is shared unless the owner explicitly opts in.
- Mobile-first; the dashboard/check-in is the primary screen.
